# Overmax v0.4.2 릴리즈 노트

> v0.4.1 이후 변경 사항 (v0.4.2)

---

## 🎮 새로워진 점 및 개선 사항

### ⬆️ 1. V-Archive 자동 업로드 (기본 꺼짐)
* **[체감 변화]**: 기록이 확정되면 ⬆ 버튼을 누르지 않아도 V-Archive에 자동으로 올라갑니다.
* **[개선 세부 요약]**:
  * 설정 > V-Archive 탭에서 켜고 끌 수 있으며, 적용 범위(결과창만 / 곡 선택 + 결과창)와 지연 시간(즉시 / 3초)을 고를 수 있습니다.
  * 값이 지연 시간 동안 바뀌지 않고 안정되면 업로드하며, 값이 바뀌거나 화면이 불안정해지면 대기 시간을 다시 셉니다. 같은 값은 다시 올리지 않습니다.
  * 결과창에서 즉시 모드를 쓸 때 MAX COMBO가 아직 표시되지 않은 값은 최대 3초 기다린 뒤 업로드합니다.
  * 업로드 대기 중에는 ⬆ 버튼이 아래에서 위로 차올라 진행 상황을 보여 줍니다.
  * 업로드 결과 토스트에 곡명과 패턴이 함께 표시됩니다. (예: "Kamui  4B MX · V-Archive: 갱신 완료")
* 💡 **이용 팁**: V-Archive 계정이 연동되어 있어야 동작하며, 기본값은 꺼짐입니다.

### 🎯 2. 결과창 Rate / Score 인식 보정
* **[체감 변화]**: 결과창 판정률 숫자 중 8이 3으로 잘못 읽히던 문제를 고쳤습니다.
* **[개선 세부 요약]**:
  * 판정률 숫자를 확대할 때 쓰던 샘플링 방식을 바꿔, 숫자 획이 뭉개지며 생기던 오인식을 줄였습니다.
  * 3인 결과창에서 판정률과 MAX COMBO를 엉뚱한 위치에서 읽던 문제를 고쳤습니다. 전체 화면 캡처 모드에서는 영향이 없었고, 고성능 캡처(GPU ROI Atlas) 모드에서만 발생했습니다.

### 🛡️ 3. 기록 데이터 보호 강화
* **[체감 변화]**: 이전 버전의 기록 파일을 열 때 플레이 기록이 지워지던 문제와, V-Archive 서버가 잠시 빈 목록을 돌려줄 때 랭크 정보가 사라지던 문제를 막았습니다.
* **[개선 세부 요약]**:
  * `is_max_combo` 컬럼이 없는 기존 기록 DB는 컬럼만 추가하는 방식으로 마이그레이션하며, 기존 기록은 그대로 보존됩니다.
  * V-Archive 응답이 비어 있으면 기존 Top-50 랭크/레이팅 정보를 지우지 않습니다.
  * 곡 번호나 난이도를 해석할 수 없는 V-Archive 기록은 저장과 불러오기에서 건너뜁니다. 잘못된 기록이 다른 곡에 붙던 문제를 막습니다.
  * 기록 DB 초기화에 실패하면 시작 로그에 명시적으로 남습니다.

### 🎮 4. 연주 및 일시정지 화면 인식
* **[체감 변화]**: 연주 중에는 일반 오버레이가 숨겨지고, 연주 기록 처리도 멈춥니다. 일시정지 화면도 인식합니다.
* **[개선 세부 요약]**:
  * 연주 화면과 일시정지 화면을 가벼운 ROI로 판정하며, 창이나 포커스가 바뀌거나 캡처에 실패하면 판정 상태를 초기화합니다.

### ⚡ 5. 선곡 화면 부담 감소 및 오버레이 버튼 수정
* **[체감 변화]**: 선곡 화면에서 같은 곡을 계속 다시 인식하던 동작이 줄어들었습니다. 결과창에서 업로드가 끝났는데도 ⬆ 버튼이 활성 상태로 남던 문제를 고쳤습니다.
* **[개선 세부 요약]**:
  * 선곡 화면에서 검증된 플레이 이벤트가 매 프레임 다시 발행되던 문제를 고쳤습니다. 이벤트는 결과창을 벗어날 때만 초기화됩니다.
  * 오버레이의 업로드 상태를 매 프레임 데이터베이스에서 조회하지 않고, 상태가 바뀌는 시점에만 갱신합니다.
  * 게임 창이 전체 화면인지 확인하는 조회도 캡처마다 하지 않고 창 조회 주기에 맞춰 수행합니다.

### 🖼️ 6. 이미지 인덱스 실시간 반영 및 기타
* **[체감 변화]**: 자켓 이미지 인덱스가 백그라운드에서 갱신되면 재시작 없이 새 자켓을 인식합니다.
* **[개선 세부 요약]**:
  * 설정 > 고급 탭에 데이터 폴더 정보와 폴더 열기 버튼이 추가되었습니다.
  * Linux 오버레이에서도 외부 도구의 표시/숨김 명령(`overlay.set_visibility`)이 동작합니다.
  * Linux 검증 환경 문서에 Sway를 추가했고, 창 모드는 사실상 지원되지 않는다고 명시했습니다.

## 🛠️ 엔지니어링 & 내부 아키텍처 변경점

### 🧭 1. 씬 판정 및 IPC 스냅샷
* **씬 상태와 안정 곡 컨텍스트 분리 (`a85c820`)**: 씬 상태는 감지 결과마다 갱신하고, `state_snapshot`과 `get_current_context`는 마지막 안정 곡 컨텍스트를 유지합니다.
* **Gameplay / Paused 씬 추가 (`0c8f61b`)**: `SceneType`에 두 씬을 추가하고 기존 씬 확정 로직을 공유합니다. 기어 구조(CENTER/LEFT/RIGHT)와 PAUSE 타이틀 ROI로 판정합니다.
* **아틀라스 재구성 (`30939f7`, `ac04180`, `fe8c586`)**: `gp_*`와 `pause_title` ROI는 씬에 종속되지 않는 `Unknown` 처리로 바꿨습니다. 3인 결과창의 두 패널 슬롯은 하나의 `ResultOpen3` 슬롯으로 합쳤고, 8px 판정 여백이 인접 슬롯에 걸치던 문제를 고쳤습니다.
* **매핑 검증 테스트 (`fb1f0e8`)**: 모든 씬 매핑이 실제 아틀라스 슬롯을 가지는지 확인하는 테스트를 추가했습니다.
* **검증 도구 (`4cb3fa2`)**: `verify_pipeline`이 전체 프레임 결과와 아틀라스 결과를 함께 비교합니다.

### 🎥 2. 캡처 및 디텍션 파이프라인
* **전체 화면 조회 스케줄 이동 (`505e691`, `2218b89`)**: 캡처마다 호출하던 `is_fullscreen` Win32 조회(`FindWindowW`, `GetWindowLongW` 등)를 `WindowQueryScheduler` 주기로 옮기고, 읽히지 않던 필드를 제거했습니다. 프레임 시간 영향은 측정하지 않았습니다.
* **DXGI 출력 교체 실패 전파 (`a58a502`)**: `DuplicateOutput1` 실패를 무시하고 옛 모니터 화면을 새 좌표로 잘라 쓰던 경로를 막았습니다. 실패 시 GDI 폴백으로 내려가며, GDI 폴백의 부작용은 별도 이슈로 남겼습니다 (리뷰 §4.4).
* **이미지 인덱스 라이브 리로드 (`63b4a54`, `6baaf48`)**: `image_db_version.txt` 변화로 `image_index.db` 교체를 감지하고, 워커에 신호를 보내 인덱스와 매처만 교체합니다. 씬과 곡 히스토리는 유지합니다.
* **이벤트 재발행 수정 (`8aae0fa`)**: 매 비결과 프레임마다 호출되던 `clear_detected_cache()`를 결과 → 비결과 전이에서만 실행하도록 옮겼습니다. 파이프라인 단위 회귀 테스트를 추가했습니다.
* **샘플러 필터 변경 (`fb4fe24`)**: 정규화 샘플러를 bilinear에서 point로 바꿨습니다.

### ⬆️ 3. V-Archive 자동 업로드 구조
* **설정 스키마 (`acb86a4`)**: `varchive.auto_upload`에 `enabled`, `scope`(`result_only` | `select_and_result`), `delay_sec`(0 | 3)을 추가했습니다. 기본값은 꺼짐, `result_only`, 3초이며 잘못된 값은 정규화합니다.
* **`AutoUploadScheduler` (`fbb3335`)**: 안정된 업로드 대상(rate 상승 또는 신규 MAX COMBO)이 범위 안에 있으면 arm하고, 곡/모드/난이도/rate/MC나 안정 상태가 바뀌면 재시작합니다. 발행된 값은 새로운 안정 값이 나올 때까지 재시도하지 않습니다.
* **결과창 대기 값 보존 (`de57807`, `e8a6ec6`)**: 불안정 프레임에서 대기 중인 값을 지우지 않고, 결과창을 벗어날 때 flush합니다. 즉시 모드에서는 MAX COMBO 없는 결과창 값을 최대 3초 기다립니다.
* **업로드 헬퍼 분리 (`5347f93`)**: 빠른 업로드 헬퍼를 `PlayContext`로 파라미터화하여, 캡처한 스냅샷을 현재 세션이 바뀐 뒤에도 확인하고 업로드할 수 있게 했습니다.
* **로그와 토스트 (`4a075d0`, `61d95d8`, `9190643`)**: 업로드 결과 로그에 곡명과 실제 업로드 값을 기록합니다. 토스트에는 곡명 주제 줄과 패턴/결과를 함께 표시합니다.

### 🗄️ 4. 데이터 계층 및 게이트웨이
* **레거시 기록 마이그레이션 (`d2954f9`)**: `DROP TABLE`을 `ALTER TABLE ADD COLUMN`으로 바꿨습니다. 기존 `ensure_schema`의 `let _ =`가 실패를 숨겨 `is_ready = true`가 되던 문제도 함께 고쳤습니다 (`d6c2546`, `19457c1`).
* **V-Archive 레코드 검증 (`e527501`, `58ead08`)**: 쓰기와 읽기 양쪽에서 파싱 불가 행을 건너뜁니다. 기존에는 `unwrap_or(0)`으로 곡 0번에 붙을 수 있었습니다.
* **빈 응답 보존 (`ef56960`)**: 증분 동기화에서 목록 추출을 `DELETE` 앞으로 옮기고, 빈 배열이면 캐시를 보존한 채 종료합니다.
* **URL 구성 (`74094d8`, `8185d53`)**: `since` 값과 `v_id` 경로 세그먼트를 값 단위로 인코딩합니다. 값에 `&`, `#`, `?`가 들어와 파라미터가 복제되거나 잘리는 문제를 막았습니다.
* **추천 엔드포인트 검증 (`070cfa8`, `24c8d4a`)**: 추천 manifest의 절대 endpoint가 provider와 같은 origin(scheme, host, port)일 때만 사용합니다.
* **자격증명 마스킹 (`b7147a8`)**: `AccountInfo`의 수동 `Debug` 구현으로 토큰과 `user_no`가 로그에 노출되지 않게 했습니다.
* **원자적 쓰기 되돌림 (`63ae6d4` → `bd421d7`)**: temp 파일 후 rename 방식은 Windows 읽기 전용 대상에서 실패할 수 있어 되돌렸습니다. 직접 `fs::write`를 유지하며, 대체 전략은 리뷰 §4.3에서 다룹니다.

### 🔌 5. IPC 및 Linux 오버레이
* **Linux 표시 명령 (`9a556ca`)**: `LinuxOverlaySnapshot`에 `overlay_visible_override`를 추가하고, `is_hidden()`이 Windows와 같은 우선순위로 적용합니다. 이 변경은 Linux 환경에서 `cargo test -p overmax-app`으로 아직 확인하지 않았습니다.
* **업로드 플래그 캐시 (`ac1063b`, `29c55d4`)**: `overlay_upload_needed`를 상태 변화 지점에서만 재계산하도록 하고, 업로드/조회/곡 DB 갱신 등 모든 상태 변화가 지나는 `refresh_overlay_data()`에서 갱신합니다.

### 🧪 6. 테스트 및 정리
* **로케일 테스트 직렬화 (`eebf0fa`)**: 로케일을 바꾸는 테스트 세 개가 공용 락을 잡도록 했습니다. 병렬 실행에서 간헐적으로 실패하던 문제를 고쳤습니다 (400회 반복 기준 59/400 실패 → 0/400).
* **재시도 계약 고정 (`e93176d`)**: `with_retry`가 SQLITE_BUSY에서 정확히 3회 시도하는 계약을 테스트로 고정했습니다. 프로덕션 코드는 바뀌지 않았습니다.
* **보류한 테스트 (`2ed4543`)**: 옛 아틀라스 배치로 덤프된 HDR 스냅샷 테스트는 `#[ignore]`로 보류했습니다.
* **정리 (`546035f`, `41b3dab`, `44f2d5f`)**: 사용하지 않는 `ResultFreestyle` ROI 설정을 제거하고, 오래된 주석을 바로잡았습니다.
